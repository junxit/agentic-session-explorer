Changelog
=========

0.6.0
-----
Delete now finishes the job, and project memory gets a home of its own.

Deleting a session used to leave most of what the harness wrote beside it. An
audit of the real stores found the backlog that had built up: 350 orphaned
session-env directories, 70 file-history directories, 15 scratchpads, 8 task
directories, 10 security-state files and 633 prompt-history rows, all belonging
to conversations that were deleted long ago.

Every artifact a session owns now goes with it
- ~/.claude/session-env/<session-id>/ and ~/.claude/tasks/<session-id>/.
- ~/.claude/security/security_warnings_state_<session-id>.{json,lock}. The id
  sits in the middle of the filename, so the old prefix search never saw them.
- /private/tmp/claude-<uid>/<encoded-project>/<session-id>/ — the scratchpad,
  keyed by both project and session, outside every store root until now.
- Prompt-history rows in ~/.claude/history.jsonl and ~/.codex/history.jsonl,
  removed through the atomic rewriter added in 0.5.0, so a harness appending
  mid-rewrite cannot lose turns.

Cascade targets are now constructed from the session id rather than searched
for by prefix, and a final check refuses any target whose name does not contain
that id. There is no pattern left that could widen onto a neighbour.

Project memory is never collateral
- A harness writes memory to outlive the conversation that produced it, so no
  session delete removes it. Every delete preview states how many memory files
  the project has and that they are being kept.
- Deleting the LAST session for a project — counted across every harness, not
  just the one you are looking at — offers an extra, unticked checkbox to remove
  the project's own state as well: memory, store folder, the ~/.claude.json
  settings entry, Gemini's folder-trust entry (whose key is lower-cased, which
  an exact match had been silently missing) and its prompt-history rows.
- New `n` key and `sx memory` command browse, export and delete memory
  directly. Each document lists its type, size and the session that wrote it:
  memory records an originSessionId, so sx can show which memories have outlived
  the conversation they came from. Memory removal is logged under its own
  op-log action, never folded into a session delete.

The backlog is visible instead of assumed
- The orphan screen reports artifacts belonging to sessions that no longer
  exist, grouped one row per class — 350 separate rows would have buried every
  other finding.

Guard changes
- ~/.claude is deliberately NOT a store root. The directories the cascade needs
  are named one at a time, so plugins, settings.json, .credentials.json and a
  282 MB vendored virtualenv stay outside the guard entirely.
- `security/` has to be a root to reach the state files, so a new
  `protected_paths()` hook refuses the virtualenv and the harness logs inside
  it. Nothing in the calling code could reach them; this makes that a guarantee.

Noted while auditing, deliberately not acted on
- ~/.claude/plans/*.md are referenced by 56 of 62 transcripts, but only by
  filename inside prose, and a plan outlives its session much as memory does.
- ~/.claude/paste-cache/*.txt is hash-named and only 3 of 30 appear in any
  transcript — too weak a link to delete on.
- Of the four legacy cascade directories, only file-history ever matches: shell
  snapshots are epoch-named, sessions/ is PID-named, and all 41 todos entries
  are <agent-id>-agent-<agent-id>.json. They are kept, and the code now says so
  rather than leaving the next reader to assume they work.

Testing
- 35 new tests. Fixed an isolation leak the memory module introduced: sx.memory
  resolves `home` in its own namespace, so patching an adapter's home did not
  cover it and a TUI test read the developer's real ~/.claude. There is now a
  regression test for exactly that.

0.5.1
-----
- The `M` key (move the project directory, then re-point its sessions) is shown
  in the footer. It was hidden, following the pattern of the vim-style
  navigation aliases j/k/g/G/tab — but those only duplicate the arrow keys,
  whereas `M` is a primary action and the more consequential of the two move
  keys, since it moves a real directory on disk rather than only session
  records. Hiding it left the riskier key as the undiscoverable one. The footer
  now reads "m Move" and "M Move dir".

0.5.0
-----
Move a project to a new directory. When you relocate a repo, every harness keeps
pointing at the old path: the sessions group under a directory that no longer
exists, get flagged as orphans, and the only thing sx offered was deletion. Now
there is an inverse of delete.

- `m` re-points the highlighted session's project at a new directory, for when
  you have already moved it by hand. `M` moves the project directory itself
  first, then does the same. `sx move --from PATH --to PATH [--relocate]` does
  either from the shell, with `--dry-run` to see the plan and stop.
- One move covers every harness holding sessions at that path. Claude re-points
  the `cwd` recorded throughout each transcript and then moves the project
  folder to the name the new path encodes to, carrying `memory/` and each
  session's `<session-id>/` sidecar with it. Codex re-points the `cwd` in its
  `session_meta` and every `turn_context`. Gemini rewrites the `.project_root`
  marker and re-keys `projects.json`. opencode updates the session's `directory`
  and `path` columns and its workspace, in one transaction.
- Only the structural working-directory field is rewritten. A path mentioned in
  tool output or in your own prose is historical record and is left as written.
  Matching is boundary-aware, so moving `proj` carries `proj/docs` along and
  leaves `proj-old` alone.
- A move is reversible: running it in reverse restores the previous state byte
  for byte, and the op-log records both endpoints so the old path stays readable
  afterwards. Moves are logged alongside deletions in `sx-deletions.log`.
- Nothing is overwritten. If the harness has already run at the new path the
  stores are merged entry by entry and any colliding name is refused, with the
  refusal shown in the confirmation rather than discovered afterwards.
- Rewrites are atomic: a new copy is written beside the original and swapped in,
  lines that cannot be parsed are copied through byte for byte (the tolerant
  JSONL reader drops them, which would have silently deleted every
  partially-written record), and the write is abandoned if the harness appended
  to the file while it was in progress.
- Re-pointing Claude's own project state is opt-in — `--claude-config`, or the
  checkbox in the dialog — covering the `~/.claude.json` `projects` entry (trust
  decision, `allowedTools`, MCP servers) and `~/.claude/history.jsonl`. Off by
  default because those files belong to a harness that may be running; the write
  is abandoned if either changes underneath it. Existing settings at the
  destination are never merged over.
- Moving the project directory itself refuses a destination that already holds
  anything, a destination inside the source, the home directory, and any
  directory containing a harness store. It runs before the stores are touched,
  so a failure leaves everything as it was. A cross-filesystem move is disclosed
  as the copy-then-delete it really is.
- opencode's shared `project.worktree` is deliberately never rewritten — a
  project row is shared with sessions that were not part of the move — and the
  plan says so instead of quietly skipping it.
- Grouping moved from `m` to `b` to make room for the move keys.

Two fixes found along the way

- Every keybinding was dead at startup. Textual focused the filter Input, which
  its CSS hides but which still received keys, so typing `o`, `e`, `d`, `r` did
  nothing except silently fill an invisible filter box. The tree now takes focus
  on mount.
- Deleting a Claude session left its `<session-id>/` directory (sub-agent
  transcripts, tool results) behind, unattributable to anything. It is now part
  of the session's correlated paths, so it is both disclosed in the delete
  preview and removed with the session.

0.4.0
-----
Safety, correctness and hardening pass. The theme: sx must never claim to have
done something it did not do, nor destroy more than its confirmation disclosed.

Deletion now tells the truth
- Delete previews and notifications report database-row removals (DeleteResult
  .note), which were previously invisible: an opencode session without a sidecar
  previewed as "Nothing to remove · 0 B" and then destroyed the whole
  conversation.
- Refused deletions are no longer reported as successes. The orphan row stays,
  the message is an error, and partial results are stated honestly. Previously a
  fully-refused bulk cleanup showed "Deleted all orphans · freed 0 B".
- Gemini's stray temp files are actually deletable: find_orphans reported paths
  outside the adapter's own store roots, so the guard refused all of them.
- Bulk orphan confirmation dry-runs each target instead of summing reported
  sizes, so the promised total matches what the guard will allow.

Deletion no longer destroys more than it discloses
- Confirmations enumerate what a folder contains (files, nested transcripts,
  memory files) before it is recursively removed.
- "Empty" project folders now state what remains instead of claiming to hold
  nothing while containing scripts, tool output or nested transcripts.
- Cascade deletion matches session ids exactly (UUID-shaped) rather than by
  substring; a session file named "a.jsonl" previously swept every ~/.claude
  state entry containing the letter "a".
- Markdown export never overwrites: colliding names get a suffix, so
  export-before-delete cannot destroy the archive it just wrote.
- A project on an unmounted volume is "unavailable", not a dead-project orphan.
- A folder's status is judged from all its sessions, and the lossy folder-name
  decode is no longer trusted to declare a project dead.
- opencode deletes database rows first and unlinks the sidecar only on success,
  removing three partial-delete paths.
- The live-session guard asks the adapter for its own activity signal (opencode
  uses the database column), and treats "unknown" as live.

Hardening
- Terminal control sequences in transcripts are replaced with visible glyphs in
  the TUI and in exports, so hostile chat content cannot retitle a window, write
  the clipboard, or clear the screen when viewed.
- Orphan table cells are Text objects: reasons embed untrusted paths, which
  Textual would otherwise parse as markup (and malformed markup wedged the
  screen).
- opencode session ids are validated before being used to build a file path.
- The delete guard refuses a store root itself.
- The op-log moved to ~/.local/state/sx/ (SX_LOG_FILE overrides), is owner-only,
  and write failures are surfaced instead of silently swallowed.

Robustness and performance
- `sx update` no longer crashes on a corrupt (non-dict) cache file; failed
  version lookups are cached so the daily throttle works; responses are bounded;
  `sx list` shows the update notice too.
- Gemini discovery no longer replays entire chat files to count messages.
- Liveness badges are briefly cached, so filtering does not stat every session
  on each keystroke.
- Runtime guards replaced asserts (stripped under `python -O`) and unguarded
  adapter lookups that could tear down the app mid-deletion.
- 21 new regression tests, including the previously impossible case of an
  adapter that refuses its own reported orphans, plus a cross-adapter invariant
  that every orphan path is deletable by its own guard. Tests no longer read the
  developer's real session stores.

0.3.0
-----
- opencode is now a fully-supported harness (browse + orphan-detect + delete).
  Unlike the file-per-session harnesses, opencode stores every session as rows
  in a shared SQLite database (~/.local/share/opencode/opencode.db). The new
  OpencodeAdapter reads sessions read-only (WAL-safe) and deletes a session by
  removing only its rows (session/message/part/todo/share) plus its
  session_diff sidecar — never the database file, never another session, and
  leaving the shared log/ files alone.
- DeleteResult gains an additive `note` field so the op-log records non-file
  removals (e.g. "deleted 8 db rows"); shown for opencode deletes.

0.2.0
-----
- Install/upgrade story: README now documents running straight from GitHub via
  `uvx` (with copy-paste `sx` aliases for zsh/bash/fish), installing as a tool,
  upgrading, and uninstalling.
- Update check: an installed, interactive `sx` checks GitHub at most once a day
  for a newer release and prints a one-line notice (TUI shows a toast). Stdlib
  only, cached, fast-timeout, fail-silent; opt out with `--no-update-check` or
  `SX_NO_UPDATE_CHECK=1`. New `sx version` and `sx update [--run]` commands.

0.1.0 (initial public release)
------------------------------
- Fix: orphan-cleanup screen `d` (delete selected) and `D` (delete all) did
  nothing — the key actions invoked async helpers without awaiting them, so the
  coroutines were discarded. They now run as Textual workers. The delete-all
  count and typed-confirm phrase derive from the on-screen list (no re-scan
  drift). Added pytest-asyncio TUI regression tests (tests/test_orphan_screen.py)
  and a full keybinding audit across every view.
- M5: pytest suite over synthetic fixtures (never touches real session data);
  README keybindings/usage refreshed; packaging verified (uv build + run).
- M4: permanent delete + Markdown export. ConfirmDeleteScreen previews exact
  files/bytes (+ Claude cascade), offers export-first, flags ● LIVE sessions and
  requires a typed phrase to delete them; bulk orphan delete needs "DELETE n".
  DeleteService adds active-session detection, store-root allowlist enforcement,
  and an append-only op-log (sx-deletions.log). Standalone `e` export action.
  Orphan-cleanup screen (`o`). Markdown exporter (sx/export.py).
- M3: grouping modes (project/date/recency, cycle with `m`), live title/project
  filter (`/`), and Claude title cleanup (strips slash-command plumbing).
- M2: interactive Textual TUI (`sx` / `sx tui`). Two panes — harness/project/session
  tree (dormant harnesses grayed) and a scrollable transcript loaded lazily in a
  background thread. Harness-agnostic Rich renderer (sx/render.py), markup-injection
  safe. Verified headless via run_test(): 35 sessions, 608-msg/3.6MB transcript opens.
- M1: read-only core + `sx list`/`sx harnesses` CLI. Verified on real files
  (34 sessions: 21 Claude, 11 Codex, 2 Gemini), zero adapter load errors.
- Adapters: Claude (in-file cwd, blocks, cascade), Codex (date-tree + session_meta),
  Gemini (mutation-log replay), plus 7 dormant harnesses (grayed until installed).
- Core: normalized Session/Message model, HarnessAdapter + JsonlFolderAdapter base,
  registry with per-adapter failure isolation, path-allowlist + dry-run delete guard.
- Scaffolded project: pyproject (uv/hatchling, sx entrypoint, py3.13+), .gitignore, README, package layout.
